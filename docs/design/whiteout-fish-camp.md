## 封面

- **玩法卖点**：冰原营地模拟经营（解压经营型）+ 结尾威胁演出
- **大纲**
  1. 开局主角（渔夫队长）站在冰原营地里，营地外堆着海量冻鱼——第一帧就看得见的资源之海。
  2. 玩家点地面走到鱼堆自动切鱼，背满走到切鱼／出餐台自动变现，现金堆肉眼可见地长高。
  3. 攒钱踩目标牌：雇渔夫（自动化）、开第二鱼区、扩建晾鱼架与货箱，营地从一条产线长成多队列流水线。
  4. 终极目标是地图顶部第一帧就矗立的篝火盛宴（金库），必须玩家亲手点开才触发结算演出。
  5. 结尾白熊袭营、士兵自动迎战，冰湖巨鲸浮出作为下一阶段钩子 → CTA。**无失败路径**，结尾战斗是演出不是挑战。

## 分析结论（流水线保留章节）

- **目标结构（动机轴）**：**解压经营型**（与「废土打捞防线」那一案的战斗压力型相反）。判断依据：
  全片 0:04–0:60 共 56 秒里画面上**没有任何威胁物、没有耐久条、没有倒计时**，玩家不会输；
  节奏完全靠「搬鱼→切鱼→变现→现金堆变高→踩牌解锁→产线变密」这个秒级正反馈小循环
  嵌套在「解锁自动化/雇员/扩建 xN → 营地繁荣」的大循环里推动。0:60 之后的白熊袭营是
  **收尾演出**：士兵自动迎战、玩家无操作、无失败判定，只承担「生存题材的压力验证 + 下阶段钩子」
  的叙事功能，不构成压力循环。因此本案的小循环**不需要**服务于战斗力转化，它自己就是奖励。
- **操作归属**：主角（渔夫队长）移动**只**由玩家点击地面驱动（`CrewModel.commandMove`），
  不点就停在原地，停手即停。范围自动交互：走近鱼堆自动切鱼（`actionRange` 36）、
  背满走近出餐台自动变现（`actionRange + 24`）。自动化只能靠购买获得（雇渔夫跑全自动小循环）。
  **无自动结算**——篝火盛宴（终极目标）必须玩家亲手点开；点开后的 3.4s 繁荣/袭营演出才自动收尾到结算卡。
  原片为摇杆走位，playable 简化为点击移动（差异点见文末）。
- **目标链**：免费/首个渔夫 → 第二鱼区 → 第二渔夫 → 篝火盛宴（终极目标，触发结算演出）。
  **原片目标牌开局即全部可见、链条无断档 ✓**（视频观察）。但**非线性原则在本模板尚未落地**：
  `CrewModel.tapPurchase` 只接受 `nextPurchase`（程序强制顺序），`CrewView.refreshPads`
  对同一坐标只显示首个未购项——付得起也不能跳买。列为差异点，不谎称已满足。
  每个循环闭合时下一目标已在场上 ✓。
- **长期锚点与地图尺度**：原片的长期锚点是营地外的巨型鱼堆（第一帧可见，资源之海）
  与冰湖及湖中巨鲸（后段浮现，下一阶段威胁）；playable 中由金库/篝火盛宴充当——
  从第一帧就矗立在地图顶部（`stations.vault` y=150）。
  主角高约占画面 8–11%（近景）/ 6%（远景），地图按四层分：
  鱼堆资源区（上）→ 围栏加工区（中）→ 出餐/顾客区（下）→ 冰湖（底，远期钩子）。
- **模板映射（操作轴）**：2D 模板 `crew`（行为树经营），代码在 `assets/scripts/crew/`，
  场景 `assets/scenes/crew.scene`（在 `common/TemplateBootstrap.ts` 以 key `crew` 注册）。
  **不是** 3D 模块拼装。四件套：CrewConfig / CrewModel / CrewView / CrewGame。

## 资源循环

- **核心资源**：冻鱼（来源：营地外的冻鱼堆 `veins`，近乎无限、敲空后 2.5s 重生）、
  现金（来源：把背上的鱼送到切鱼/出餐台投递变现，`goldPerBar` 每条 5）。
  原片里现金以可见的堆叠形式增长（frame 02/04）。
- **循环 1 · 手动切鱼变现（开局即在）**：
  点地面走到鱼堆 → 进入 `actionRange` 自动切鱼（`strikeInterval` 0.28s 一次、每次产 1 条）→
  背上最多 3 条（`workerCapacity`）→ 走到切鱼/出餐台 → `depositTime` 0.3s 完成投递 →
  现金 +3×5=15 → 现金堆变高、锯台迸火花。
  **一趟满载恰好等于第一个目标牌的价格**，玩家跑完第一趟循环立刻买得起自动化。
- **循环 2 · 解锁自动化与扩建（踩目标牌后出现，地编预留空位）**：
  攒钱 → 点目标牌 → 雇渔夫（行为树雇员接管小循环：感知锁定最近有货鱼堆 → 自动接近 →
  自动切鱼 → 背满自动回投）/ 解锁第二鱼区（新一片鱼堆亮起，产能翻倍）→
  产线变密、现金增速变快 → 攒够钱点燃篝火盛宴。
  原片对应的是自动切鱼机 + 传送带 + 晾鱼架塔 + 货箱 + 更多雇员（frame 03/04/05）。
- **战斗循环**：**本案没有战斗循环**。结尾白熊袭营/敌潮是一次性演出（`CrewPhase.Boom`，
  3.4s），玩家不操作、不掉血、不失败，不参与任何资源循环。
- **核心逻辑**：操作重心从「玩家自己跑鱼→变现」转移到「站着看雇员跑、专心攒钱踩牌」；
  压力**不发生转移**（全程无压力），取而代之的是**密度**的转移：从一条手动产线
  转移到多队列全速运转的繁荣画面（frame 05），最后由篝火盛宴一次性兑现为演出高潮。

### 数值设计

**大小关系原则**（美术/程序可自行调绝对值，不许破坏关系）：
1. 终极目标（篝火盛宴）最贵，且位于目标链末位——攒钱曲线的终点。
2. 目标链价格严格递增：15 < 30 < 45 < 80（代码现值）。原片目标牌观察值同样递增：150 < 200 < 350。
3. **首个目标必须等于主角手动跑一趟的收入**：背包 3 × 每条 5 金 = 15 金/趟 = 第一个目标牌价格。
   这条关系是「教会小循环 → 立刻兑现成自动化」的引导支点，改数值时必须一起改。

5. 感知半径（300）远大于交互半径（36）：雇员一进场就能自己找到活干，不需要玩家指派。
6. 结尾演出时长（3.4s）应短于玩家攒完整条链的时间——演出是奖励，不是等待。
