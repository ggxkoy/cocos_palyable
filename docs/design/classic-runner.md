## 封面

- **玩法卖点**：三轨躲避跑酷（反应型），换皮 Subway Surfers 类经典跑酷
- **大纲**
  1. 开局角色已经在跑，玩家第一步就是点屏幕左/右半边换车道——没有起步按钮、没有菜单。
  2. 障碍波（火车/栏杆）从画面深处逼近，每波至少留一条安全车道，玩家必须提前判断往哪挪。
  3. 金币永远成列长在那条没有障碍的车道上，于是「躲」和「贪」是同一个动作——躲对了就顺手吃到钱。
  4. 双列火车对开夹击开始出现，安全车道从两条收窄到一条，压力靠概率而非时间递增。
  5. 目标：撑满 18 秒倒计时即通关（`FINISH!`）；中途撞上任何障碍立即失败（`CRASH!`）。单次跑动，不可复活重试，两种结局都直接进结算卡 + CTA。

## 分析结论（流水线保留章节）

- **目标结构（动机轴）**：反应躲避型（非战斗压力型、非解压经营型）。判断依据：原片全程没有资源加工链、没有购买解锁，玩家唯一的决策是「下一波往哪条道挪」；金币是记分与炫耀，不是生产资料。因此小循环不做「收集→转化→验证」，只做「预判→换道→顺手收币」。
- **操作归属**：原片为滑动操作（左右滑换道、上滑跳、下滑铲）。playable 简化为**点左半屏向左、点右半屏向右**（`RunnerView.handleTouchEnd` 按触点相对屏幕中心分左右），降低门槛。前进是自动的（角色恒定向前，屏幕上表现为障碍物向下推进），换道**必须**玩家操作，无自动躲避、无自动结算。纵向动作（跳/铲）未落地。
- **目标链**：本案无购买、无解锁，故无目标链。唯一目标是「撑到倒计时归零」，全程可见（HUD 右上角 Time 读秒）。非线性原则在此退化为：每一波障碍都同时给出多条可选车道，选哪条由玩家判断，程序不强制路线。
- **长期锚点与地图尺度**：长期锚点是 HUD 上持续倒数的 Time 与持续上涨的 Coins。地图尺度：竖屏单屏无滚动分层，三条车道横向铺满路面（web 390 坐标下路宽 300、车道间距 95），角色固定在屏幕下方 y=700 处，约占画面高度 8.5%（56×72 占位盒 / 844）。
- **模板映射（操作轴）**：2D 模板 `runner`，四件套 `assets/scripts/runner/`（RunnerConfig / RunnerModel / RunnerView / RunnerGame），场景 `assets/scenes/runner.scene`，在 `common/TemplateBootstrap.ts` 以键名 `runner` 注册。**不是** 3D 模块拼装。

## 资源循环

- **核心资源**：金币（来源：安全车道上的金币列，唯一来源，只用于计分不用于消费）、剩余时间（来源：开局给定 18 秒，只减不增）。
- **循环 1 · 躲避-收币（开局即在）**：
  障碍波在画面顶端生成（进度 0）→ 以 0.55 进度/秒向玩家推进 →
  玩家读出这波占了哪几条道 → 点左/右半屏换道（角色横向阻尼滑移并侧倾）→
  站到没有障碍的那条道上 → 同一条道上排着 3 枚一列的金币 → 依次进入判定窗口被吸收，
  HUD 金币数跳动 + 角色身前爆 10 粒火花 → 下一波已经在路上，回到第一步。
  **躲对了才有钱**：金币只生成在本波没有障碍的车道（`RunnerModel.spawnWave` 取洗牌后第一条未被障碍占用的车道），躲避与收益共用同一次点击。
- **循环 2（解锁后出现，地编预留空位）**：无。原片的道具循环（磁铁吸币、喷气背包、分数倍率，见 frame 05）本次不落地，见文末差异点。
- **战斗循环**（战斗压力型）：不适用，本案无敌人、无攻击、无生命值，撞击即一击结束。
- **核心逻辑**：操作重心不发生转移（全程只有换道一个动作）；压力从「单列障碍，两条道可选」转移到「双列夹击，只剩一条道可选」，靠 0.35 的双障碍概率随机加压，而不是按时间硬编排。

> **非线性原则**：全程无「第 N 秒触发 X」的剧本。下表只有波次生成与收尾静默是计时器
> （节奏参数），其余推进完全由玩家操作与场上状态驱动。

### 数值设计

**大小关系原则**（可调绝对值，不许破坏关系）：
1. 生成间隔（0.85s）必须小于单件在场时长（1.1 ÷ 0.55 ≈ 2.0s），否则屏上出现空档、节奏散掉——当前约 2.4 波同屏。
2. 每波障碍数必须 < 车道数：3 条道最多放 2 条障碍，永远留至少一条活路。
3. 金币列永远长在本波没有障碍的车道上——躲避与收益同解，玩家不需要在「安全」和「贪」之间二选一。
4. 双列夹击概率（0.35）显著小于单列（0.65）：险情是点缀不是常态。
5. 金币出现概率（0.9）接近必现：几乎每波都有正反馈。
6. 判定窗口宽度（0.94-0.82=0.12 进度 ≈ 0.22s）要够玩家在障碍贴脸前完成换道，但不能宽到「擦边不死」。
7. 收尾静默（2.5s）必须大于单件在场时长（约 2.0s），保证通关那一刻场上已经清空。

本案**无消费点**（跑酷无购买、无解锁），故不填「交互点 / 需要金币数」表；金币纯计分，面值恒为 1。节奏参数见下表：

| 交互点 | 需要金币数 | 备注 |
| --- | --- | --- |
| （无购买/解锁点） | — | 金币只进 HUD 计数，不参与任何兑换 |

属性数值：车道 3 条（索引 -1/0/1，出生 0）；主角无生命值，一击即死；单枚金币 +1；单局时长 18s；障碍推进速度 0.55 进度/秒；撞击判定窗口 0.82–0.94；金币列 3 枚、列内间隔 0.07 进度（约 0.25s 吃完一列）。

### 敌人攻击机制（战斗压力型）

本案**不是**战斗压力型：没有敌人 AI、没有攻击结算、没有耐久条。压力源是无生命的障碍波，节奏如下：

| 时间节点 | 描述说明 | 画面参考 |
| --- | --- | --- |
| 初始阶段（0.6s 起） | 每 0.85s 一波；波内洗牌三条车道，1 条放障碍（65%）或 2 条放障碍（35%） | 02-run-start.png |
| 险情段（随机出现，非定时） | 双障碍波 = 原片的双列火车对开夹击，只剩一条安全道 | 04-double-trains.png |
| 撞击 | 同车道且进度进入 0.82–0.94 → 立即判负，无护盾、无 hoverboard 救援 | 04-double-trains.png |
| 收尾（剩余 2.5s） | 停止生成，场面自然清空 | — |
