## 封面

- **玩法卖点**：数值跑酷（战斗压力型·成长验证子类）——两条路线取舍，人数即火力，终局数量对撞
- **大纲**
  1. 玩家带一支小队在笔直跑道上自动向前跑并自动开火，手指左右拖动只负责选路。
  2. 跑道被中间的矮墙分成两条：**左路**堵着带血量的冰块（画面实测 `143`），
     打碎它后面是成排的 `+999` 大额补充；**右路**是一级级 `+1` 的台阶，稳但慢。
  3. 核心取舍：**队伍人数就是 DPS**。人少打不碎左路的块（撞上白撞），只能走右路一点点攒；
     人攒够了才吃得下 `+999` 的暴涨——正反馈滚雪球。
  4. 跑道尽头是数量写在头顶的红色敌军（画面实测 `500`）与一名 BOSS，冲进去做数量对撞。
  5. 打不过即失败，可**重新挑战 1 次**（对标案规则）；赢下对撞出结算卡与 CTA。

## 分析结论（流水线保留章节）

- **目标结构（动机轴）**：**战斗压力型**，「成长验证」子类（依据：终点有真实敌军数量与对撞判定）。
  与「废土打捞防线」那种持续挨打型的差别：**全程无人攻击玩家**，压力来自
  「跑到终点时我的数字够不够」这一个悬念，由**始终可见的敌军数字**施加。
  压力曲线单调上升、终点一次性释放。
- **本案真正的设计核心（与常见「±/× 成对门」形态的关键差异）**：
  **资源与战斗力是同一个数字**——人数既是收益也是 DPS。于是「能不能打碎那块 143」
  本身就是对成长的即时检验，形成 **人多 → 打得碎 → 拿 +999 → 更多人** 的正反馈滚雪球；
  而 `+1` 台阶是**保底路径**，保证人少时也永远有路可走、不会卡死。
  这套结构比「选左门还是右门」的纯算术更耐玩，也是本案必须优先还原的东西。
- **操作归属**：横向选路 **100% 由玩家驱动**（拖动横移，松手保持当前横向位置，
  无自动选路、无自动纠偏、无自动结算）。
  **前进为题材恒定项**：跑酷的「跑」不是玩家决策，全部决策带宽用在选路上——
  与仓库「禁止自动走位」原则不冲突（同 `classic-runner` 案的既有判例）。
  自动开火是**题材天然项**而非购买获得（集群射击不可能手动点射）。
- **目标链**：路上的块与台阶即连续目标，天然无断档——**当前块尚未打碎时，
  下一段路线已在视野内**（依据：封面帧里左路三块冰块与右路台阶同时在画面中）。
  终极目标（敌军 `500`）**第一帧即可见**。
  **非线性原则**：全片**没有任何秒表事件**——所有块、台阶、终局都由**跑过的距离**触发。
- **长期锚点与地图尺度**：红色敌军与头顶数字压在跑道尽头，开局即在画面内（长期锚点）。
  跑道笔直、两条路、两侧有矮护栏；单兵身高 1.7m，队伍规模用**方阵扩散**表达
  （封面帧里约 20 人排成 4 排的密集方阵），让「变强」肉眼可见而不只是数字变大。
- **模板映射（操作轴）**：3D 模块拼装，新建 `playables/numrun3d/`。
  **不复用** 2D 的 `runner` 模板（那是切道躲障碍的 2D 切片，没有集群、血量块与数量对撞），
  但其实测节奏参数可作落地起点（见「数值设计」）。

## 资源循环

- **核心资源**：队伍人数（**唯一硬通货**，同时是收益、DPS 与终局战力）。
- **循环 1 · 稳定攒（右路，保底）**：踩 `+1` 台阶 → 人数逐级 +1 → 方阵变宽 → DPS 变高。
  永远可走，永远不会卡死。
- **循环 2 · 赌一把（左路，高回报）**：对准冰块持续开火 → 血量数字递减 →
  在撞上之前打碎 → 吃到后面成排的 `+999` → 人数暴涨 → DPS 暴涨 → 下一块更大的也打得碎。
  **打不碎则撞上受损**（惩罚，见数值设计原则 4）。
- **战斗循环（终局一次性）**：人数 × 火力 → 与敌军数字对撞 → 双方数字同步递减 → 谁先归零谁输。
- **核心逻辑**：操作重心**不转移**（全程只有横移），转移的是**风险偏好**——
  前期人少只能走右路保底，中期开始够得着左路小块，后期滚起雪球后左路才是正解。
  玩家要判断的是「**我现在的 DPS 够不够吃下这一块**」，这是本案唯一的决策深度，
  数值设计必须保护它（见原则 2）。

## 地编需求

- **布局参考**（依据 `01-cover-gameplay.png` 直读）：竖屏，相机在方阵**后上方**跟随，
  笔直跑道向远处收敛；跑道两侧有灰色矮护栏，护栏外是深色水面/夜空。
  跑道被**中间一道矮隔墙**分成左右两条路：
  **左路**——依次摆放带血量的冰块，块后紧跟成排的 `+999` 面板；
  **右路**——连续的 `+1` 台阶（阶梯状，带高光粒子）。
  跑道尽头是红色敌军人海 + BOSS + 数字牌。
- **分段建议**（拟定）：
  **教学段**：右路先出现两级 `+1`，左路给一块**血量很低**的冰块（让玩家第一次就打碎，
  建立「打碎有大奖」的认知）。
  **抉择段**：冰块血量升到玩家当前 DPS 的临界附近，逼出真正的判断。
  **加压段**：块血量继续上升，`+999` 面板成排出现（回报也放大）。
  **终局段**：跑道收束，敌军列阵。
- **可视距要求（保证目标链无断档）**：相机必须能同时看到**当前块与下一段路线**
  （封面帧里三块冰块 + 两级台阶同框）——落地以此为验收标准，不以美术构图为准。

### 数值设计

**大小关系原则**（可调绝对值，不许破坏关系——这几条是本案玩法深度的全部来源）：
1. **起始人数必须小到让第一次 `+1` 都看得见变化**（方阵宽度肉眼可辨）。
2. **冰块血量必须跟着「玩家此刻的期望 DPS」走**，让每一块都卡在
   「刚好打得碎 / 刚好差一点」的临界带上。**若块血量恒定，中后期会退化成无脑走左路**——
   这条是本案深度的命门。
3. **`+999` 的回报必须显著大于同段右路 `+1` 的累计**（否则没人愿意冒险），
   但**不能大到一次翻盘**（否则前面的稳健积累失去意义）。
4. **撞块惩罚必须真的痛**（扣人 + 减速），否则「打不碎也去撞」成为无风险策略。
5. **右路保底速率必须能让最差路线也走到终局**（可以打不过，但不能卡死在半路）。
6. **终局敌军数字**必须满足：稳健路线**险胜**、贪心失败若干次的路线**明确打不过**、
   完美滚雪球路线**碾压**。这是全案最重要的一个数字。

**画面直读的锚点数值**（实测，不是拟定）：冰块血量 `143`；补充面板 `+999`；
台阶 `+1`；终局敌军 `500`。

> **落地必做（本仓库硬规则：数值平衡靠量不靠猜）**：上述四个锚点来自**单帧**，
> 既不知道它们出现在流程的第几段，也不知道玩家当时的人数，**不能直接当配置抄**。
> 落地后必须：① 按原则 2 把块血量做成「随进度递增」的序列而非常数；
> ② 用脚本机器人跑三条路线（全右路保底 / 稳健混合 / 全左路贪心）+ 对终局敌军数字
> 做参数扫描，确认「稳健险胜、贪心失手必败、卡死不可能」；③ 把定档值与被否掉的档位
> 写回本节。参照 `army-salvage-defense.md` 的做法。
>
> 节奏参照（来自本仓库 `runner` 模板实测，可作落地起点）：生成间隔 0.85s、
> 单件在场约 2.0s、同屏约 2.4 波。本案路段长度应按「当前块与下一段同框」反推。

属性数值（拟定，待校准）：起始人数 {待定，建议 5}；撞块扣人 {待定}；

### 与模板的差异点（落地状态）

> 全部未落地（本案尚未实现）。按优先级排序。

1. **集群渲染**：人数可达数百而同屏实例必须封顶——「方阵加密 + 数字放大」的表达方案是
   最大技术风险，落地时先做这一块的可行性验证。
2. **人数即 DPS 的耦合**：`squad` 模块要把人数直接换算成弹幕伤害输出，
   `block` 的血量扣减依赖它——这是本案的机制核心，两个模块的接口要先定死。
3. **连续横移 + 隔墙开口**：现有 2D `runner` 是离散切道，本案要连续横向位置，
   且换路只能在开口处——决策窗口长度由开口位置决定，进 `lane` 模块。
4. **块血量随进度递增**：不能做成常数（原则 2），需要一个跟随「期望 DPS 曲线」的序列生成器。
5. **相机后上方跟随**：现有相机模块是等距俯视，需增加机位参数。
6. **重试回退点**：失败后回到最后一个路段之前而非从头——需要 Sim 支持状态快照。
7. **同题材另一变体（本次不做，备查）**：市面上更常见的是「成对 `+N` / `×N` 数字门」形态，
   决策深度来自「加法与乘法的交叉点」。本参考片**不是**这一形态；
   若后续要做该变体，另起一份策划案，不要混进本文。
8. **原片未解之处**：是否存在独立队长单位、是否有人数 HUD、撞块的具体惩罚量、
   块血量的实际递增曲线——均因原片不可下载而无法实测，已在各章标 {待定}。
